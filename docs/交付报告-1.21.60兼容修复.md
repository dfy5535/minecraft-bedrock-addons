## 5. 仍存在的兼容问题（如实标注）

### 5.1 zombie：1.26 专属实体字段在 1.21.60 schema 下按默认值处理

把实体 `format_version` 降到 1.21.60 后，引擎按 **1.21.60 schema** 校验，以下 1.26 才有的写法被忽略（实体本身正常加载，AI 正常跑）：

| 字段 | 涉及实体 | 现象 |
|---|---|---|
| `minecraft:behavior.ranged_attack.attack_range` | stray / drowned / husk / skeleton / zombie 等 | `child 'attack_range' not valid here` |
| `minecraft:behavior.ranged_attack.attack_interval`（对象形态） | 同上 | 期望 float，对象被忽略 |
| `sound_interval` / `cooldown_range` / `digging_duration_range` 的区间对象 | piglin / zombie / husk / drowned / zombie_villager 等 | `Missing range_min/range_max → defaulting to 0` |

**影响**：远程攻击的距离/间隔、部分计时区间回落到默认值 —— AI 仍可用，但**不是 1.26 下的调校值**。
**为什么没直接改掉**：这些字段的 1.21.60 合法写法我无法在 1.21.60 上实测确认；贸然改写有把当前版本也改坏的风险。
**建议**：如需完全消除，应在拿到 1.21.60 环境后逐字段改写（属于「高版本增强版/基础版」分叉的典型场景）。

### 5.2 deepvein：`minecraft:piercing_weapon` 在 1.21.60 被忽略

`items/titanium_spear.json` 使用了 **1.21.130 才新增**的 `minecraft:piercing_weapon`。
- 1.21.60：组件被忽略，**长矛本身正常**，只是没有穿刺效果；
- 1.21.130+：正常生效。
- **没有删除它**（避免削减高版本玩法），已在交付中标注。

# 追加：零代价版与「最高兼容版本」（2026-10-17）

## A. 最高兼容版本

| 项 | 值 | 依据 |
|---|---|---|
| **声明的最低版本** | `min_engine_version = [1,21,60]` | 这是**下限**，不封顶 |
| **实测最高版本** | **1.26.52.3** | 两个版本（满血/兼容）都在该 BDS 上实际启动、加载、跑 AI |
| **理论上限** | 无已知上限 | 官方 v2-overview：声明 1.x 的包「will continue to be supported in Minecraft for many years to come」；只要引擎仍提供 `@minecraft/server` 1.x 就能跑 |
| **实际风险点** | Mojang 若某天停发 1.x 模块，则需升到 2.x | 届时要把脚本整体迁到 v2 语义 |

> 结论：**1.21.60（下限）→ 1.26.52.3（已实测上限）**，向上无硬顶。

## B. 「零代价」的硬约束（必须知道的一条）

`format_version` 决定引擎用**哪一版 schema** 校验文件。把它设成 `1.21.60` 后，**任何引擎**（包括 1.26.52.3）
都会按 1.21.60 的 schema 校验 —— 于是**1.21.60 之后才新增的组件会被忽略**。

因此：**「1.21.60 可运行」与「1.26 满血功能」在单包内不可兼得**，只对用到新组件的 MOD 成立。

## D. 还原过程中发现的原版既存缺陷（未修，如实登记）

原版 `zombie_villager.json` 的 `minecraft:behavior.random_search_and_dig` 中：
`cooldown_range` / `digging_duration_range` 写成 `{"min":..,"max":..}`，
**1.26 schema 也不认**（报 `Missing range_min/range_max`，按 0 兜底）。

尝试过两种修法，均**导致实体加载失败**（`Entity 'minecraft:zombie' failed to load`）：
- `{"range_min":..,"range_max":..}` → 报「成员不在 schema 中」
- `[min, max]` 数组 → 同样失败

故**回退原样**（该写法实体能正常加载，只是这两个区间按 0 兜底）。属既存问题，不是本次引入。

## E. 建议

- DeepVein / LuckyBlock / LuckyClover → 单版本即可，实测无代价
